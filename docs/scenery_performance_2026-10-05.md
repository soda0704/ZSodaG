# Диагностика производительности снежного окружения — 2026-10-05

Проверено в GodotSteam 4.7.2, D3D12 Forward+, RTX 5080, viewport 3840×2160, scale 100%. Загружена Base_Blockout_v03. Камера фиксирована, игрок неподвижен; это контрольный рендер, а не профиль полного игрового прохождения. Перед замерами отключены VSync и лимит FPS только в тестовом процессе. Сохранённые пользовательские настройки не менялись. Для каждой конфигурации: 100 кадров прогрева, 480 кадров измерений.

## Подтверждённые факторы

- Ранее увеличенные mesh_size=96 и дальность=6000 увеличивали число отображаемых примитивов с 765716 до 1935980 (2,53 раза). В проекте уже восстановлены mesh_size=48 и дальность 2600. Контроль 4K: медиана 3,351 → 3,614 мс при возврате тяжёлых настроек. На данной видеокарте это не воспроизводит тяжёлую постоянную просадку само по себе.
- В пользовательском launcher_settings.json установлены FPS=30, VSync=true, MSAA=3 (8×), SSIL=true, SSR=true, разрешение 3840×2160. FPS=30 задаёт потолок частоты; это отдельный фактор от реальной стоимости кадра.
- MSAA 8× увеличивает счётчик памяти текстур/буферов с 1423,91 до 2503,91 МиБ. Отключение MSAA: медиана 3,466 → 2,619 мс. Отключение SSIL/SSR: 3,466 → 2,790 мс. Отключение всех трёх: 1,936 мс. После возврата настроек: 3,456 мс. Это последовательные сравнения одного процесса; значения GPU могут включать очередь драйвера, поэтому вывод основан прежде всего на времени кадра и памяти.
- Отключение фонового леса на востоке: 3,351 → 3,308 мс; на севере 2,554 → 2,497 мс. В этих видах лес не является основной причиной просадок. Тест не исключает другие ракурсы и движение камеры.
- Отключение обработки узлов полной игровой сцены: 3,315 → 3,371 мс; дополнительно отключение физического пространства: 3,333 мс. Подтверждённого постоянного узкого места в игровой логике/физике в неподвижном контрольном виде не найдено.

## Панорама 4K

Native texture import process/size_limit=4096. Runtime размер подтверждён: 4096×2048. HDR, сжатие и mipmaps сохранены, исходник 8192×4096 сохранён для редактирования. Расход памяти текстур полной сцены уменьшился ровно на 32 МиБ (2535,91 → 2503,91). Медиана восточного вида: 8K 3,303 мс, 4K 3,351 мс; ускорение в пределах шума и не подтверждено. Это экономия памяти, не основное устранение лагов.

## Стартовые паузы и пределы диагностики

Полная сцена: добавление/загрузка 1660 мс, максимальный кадр первых 600 кадров 401,36 мс. Движок предупреждает о чтении геометрии с GPU при runtime bake навигации в containment_encounter.gd:46. При отключении только запуска этой сборки в памяти тестового процесса максимум остаётся 380,39 мс. Следовательно, навигация не объясняет всю стартовую паузу. Наружная сцена отдельно: загрузка 487 мс, первый кадр 134,84 мс. Основная дополнительная стартовая нагрузка находится в инициализации полной базы, а не только в фоновых деревьях/панораме; конкретный оставшийся источник требует профиля startup (CSG/коллизии/загрузка моделей/драйвер). Кадр запуска нельзя смешивать с постоянной частотой кадров.

В текущем фиксированном виде после прогрева тяжёлые лаги не воспроизведены: медиана около 3,3–3,5 мс, p95 около 8–11 мс. Для оставшейся проблемы нужен профиль движения по проблемному месту в обычном игровом запуске и редакторе, отдельно от первых секунд загрузки. Не подтверждено, что все пользовательские лаги устранены.

Проверка world_boundary_regression после импорта 4K: RESULT [], включая фактический размер панорамы и физические границы.

Логи и временные диагностические скрипты: tools/.local/scenery-review/lag-8k.log, lag-4k.log, logic-probe.log, startup-no-nav.log, startup-exterior.log, boundary-4k.log. Эти файлы находятся в игнорируемой локальной папке; в runtime новые диагностические скрипты не подключены.

Ближайшая практическая настройка через меню графики: проверить MSAA 2× вместо 8×, SSIL/SSR по одному отключить для сравнения; для проверки частоты выше 30 изменить лимит FPS. Постоянную оптимизацию gameplay-кода без найденного узкого места не выполнять.
