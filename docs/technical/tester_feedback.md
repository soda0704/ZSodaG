# Обратная связь тестеров

## Поведение

Форма открывается по **F8 по умолчанию** (переназначается в «Управлении»), из Esc и главного меню. Игра продолжает идти; ввод персонажа блокируется существующим `GameMenu`. Отчёты принадлежат самому тестеру, включая гостя кооп-сессии. Git, GitHub и авторизация тестеру не нужны.

Обязательны заголовок и описание. Дополнительно выбираются тип («Ошибка», «Идея», «Впечатления»), влияние ошибки и шаги воспроизведения. Скриншот необязателен: новый отчёт получает снимок игры без меню; «Снять игру» обновляет снимок и контекст. Можно выбрать PNG/JPG до 20 МБ или убрать вложение. Изображение уменьшается с сохранением пропорций до 1920 пикселей по большей стороне.

Контекст относится к открытию формы/повторному снимку: версия сборки, движок, сцена, день, стадия задания, питание, топливо, проводка, роль хоста/гостя, число участников, координаты и модель игрока, предмет в руках, здоровье, сон и транспорт. Также записываются ОС, GPU, режим рендеринга, разрешение и FPS. Имена друзей, Steam ID, IP, полный сейв и личные пути не включаются.

Сначала создаётся уникальный ZIP в `user://feedback`: `report.json`, читаемый `report.txt`, необязательный `screenshot.png`. Пакет записывается во временный файл, проверяется и переименовывается. Только после этого начинается отправка. Пакеты не перезаписываются. Кнопки открывают папку отчётов и копируют путь к ZIP.

Esc и повторное открытие сохраняют черновик в памяти. После успешного сохранения/отправки следующее открытие создаёт новый отчёт. При ошибке отправки доступны прежняя форма и повтор. После перезапуска игры ZIP можно открыть через «Загрузить отчёт» и отправить с прежним ID. Несохранённый черновик перезапуск не переживает. Фоновых отправок без нажатия кнопки нет.

## Устройство и доставка

`tester_feedback_store.gd` собирает диагностику и пакет; `tester_feedback.gd` управляет формой, снимком и `HTTPRequest`. `GameMenu.MenuView.FEEDBACK` возвращает пользователя в Esc или непосредственно в игру/главное меню. F8 не закрывает настройки с незаписанными изменениями; буква «ё» при вводе текста не открывает консоль.

`tools/feedback_service/worker.mjs` принимает multipart `report` + необязательный `screenshot` на `POST /reports`. Он создаёт файлы `reports/<report_id>/report.json` и `screenshot.png` в отдельном **закрытом** GitHub-репозитории, затем Issue с описанием, контекстом и ссылками на файлы. PR не нужен. Команда видит вложения после входа в GitHub; тестер получает подтверждение без аккаунта. Inline-превью картинки в закрытом репозитории не гарантируется; ссылка ведёт к файлу.

Токен GitHub находится только в секрете Worker; игра содержит публичный HTTPS-адрес. Сервер проверяет фактический размер запроса, структуру, поля, ID и PNG, ограничивает обращения до 5 в минуту на IP, исключает упоминания из текста. Durable Object по ID хранит отпечаток и квитанцию: одинаковый повтор возвращает прежний результат, другое содержимое с тем же ID отклоняется. После потерянного ответа GitHub проверяются существующие файлы/Issue. Клиент подтверждает доставку только при HTTP 2xx с JSON `ok: true` и совпадающим `report_id`.

Это приём для небольшой группы без авторизации отправителей. Массовый открытый тест потребует дополнительной защиты и политики хранения. Система не меняет сюжет, сейвы и состояние другого игрока.

## Настройка

- Разметка и стили: `scenes/ui/tester_feedback.tscn`, общий `menu_theme.tres`.
- Адрес и timeout: **`assets/config/tester_feedback.tres`** в Inspector. `endpoint` — `https://northernlab-feedback.denserbinlol.workers.dev/reports`; сервис подключён 13 октября 2026 года к закрытому `soda0704/NorthernLab-feedback`, ветке `main`. Windows-сборка пересобрана с этим адресом. ZIP сохраняется перед отправкой и остаётся доступен при сбое.
- Однократное подключение: [инструкция сервиса](../../tools/feedback_service/README.md).

Используются штатные [HTTPRequest](https://docs.godotengine.org/en/stable/classes/class_httprequest.html), [ZIPPacker](https://docs.godotengine.org/en/stable/classes/class_zippacker.html), [GitHub Issues API](https://docs.github.com/en/rest/issues/issues), [Contents API](https://docs.github.com/en/rest/repos/contents). Снимок берётся после [отрисовки Viewport](https://docs.godotengine.org/en/stable/classes/class_viewport.html).

## Проверка

```powershell
tools/.local/godotsteam-editor/godot.exe --headless --path . --script res://tools/tests/tester_feedback_regression.gd
tools/.local/godotsteam-editor/godot.exe --path . --script res://tools/tests/tester_feedback_regression.gd -- --capture
node --test tools/feedback_service/worker.test.mjs
node tools/tests/run_tester_feedback_delivery.mjs
```

Проверяются ZIP, кириллица, ошибки записи/изображений, размеры, черновик, контекст реальной базы и меню, соответствие F8 событию обычной клавиатуры. Графический запуск проверяет снимок без формы и UI при 720p. Проверка формы отключает отправку в собственной копии конфигурации; файл с рабочим адресом остаётся неизменным. Тест сервиса проверяет ограничения, повторные/одновременные запросы и восстановление после потерянного ответа. Последний тест проводит реальный `HTTPRequest` из Godot через локальный HTTP-сервер и рабочий код Worker с подменённым GitHub: JSON/PNG доходят до адаптера, неверные ответы/timeout не считаются доставкой, повтор/загрузка ZIP не создают второй Issue. Этот набор не отправляет тестовые отчёты в рабочий GitHub.

Локальные проверки не подтверждают размещение сервиса. 13 октября 2026 года дополнительно проверена настоящая доставка: [Issue №1](https://github.com/soda0704/NorthernLab-feedback/issues/1), JSON и PNG созданы рабочим Worker. Намеренная потеря первого ответа, повтор и загрузка сохранённого ZIP не создали второй Issue; прямая HTTPS-отправка из Godot тоже прошла. Файлы проверены под аккаунтом владельца. Приглашение `xDiR0` ожидает принятия; затем нужно проверить ссылки под его аккаунтом. Отчёты хоста/гостя на двух компьютерах через Steam остаются отдельной проверкой.

После перевыпуска токена подтверждён тип `GITHUB_TOKEN: secret_text` в Cloudflare и повторена настоящая доставка новым отчётом: [Issue №2](https://github.com/soda0704/NorthernLab-feedback/issues/2). JSON/PNG и повторные квитанции проверены; два тестовых отчёта создали ровно два Issue.

При вызове отчёта поверх открытого журнала сначала снимается кадр с физической книгой, руками и содержимым страниц, затем журнал закрывается для формы. Ввод во время захвата заблокирован. Само окно отчёта исключено из снимка; кнопка повторного снимка захватывает текущее состояние игры. Горячая клавиша обрабатывается до GUI-навигации, поэтому фокус на странице журнала её не поглощает; она не вмешивается в переназначение и набор букв в текстовых полях. Проверка обоих персонажей, F8/F9, кадров и повторного снимка — `feedback_journal_capture_regression.gd`, без отправки в сервис.
