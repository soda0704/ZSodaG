# Steam networking prototype

## Решение

Northern Lab использует модель сюжетного кооператива с авторитетным хостом:

- один игрок создаёт Steam Lobby и одновременно запускает игровую симуляцию;
- второй игрок находит хоста через Lobby ID, список совместимых лобби или Steam Invite;
- игровой трафик идёт через `SteamMultiplayerPeer` поверх Steam Networking Sockets;
- `server_relay = true` направляет обмен клиента через хост, а Steam Datagram Relay при необходимости скрывает IP и обходит NAT;
- выделенный игровой сервер для прототипа не требуется.

Steam Lobby не хранит и не симулирует мир. Оно отвечает за обнаружение сессии, список участников, приглашения и метаданные. Состояние сюжетной игры остаётся у хоста.

## Изоляция от level design

Прототип находится в отдельной сцене:

`res://scenes/tests/network/network_prototype.tscn`

Сцена содержит отдельный салон вертолёта для ожидания и переиспользуемую тестовую зону базы `door_gameplay_area.tscn`. Она не инстансит и не изменяет `Base_Blockout_v03.tscn`. Сетевая механика сначала проверяется здесь, после чего переносится в production-сцены отдельной задачей совместно с владельцем уровня.

## Авторитет и синхронизация

Прототип не принимает координаты игрока от клиента.

1. Клиент отправляет хосту нормализованный вектор движения, поворот, sprint и порядковые номера одноразовых действий.
2. Хост проверяет `remote_sender_id`, ограничивает входные значения и выполняет `move_and_slide()`.
3. Хост рассылает состояние с частотой `20 Hz`.
4. Владелец персонажа использует локальное предсказание с плавной коррекцией.
5. Удалённый персонаж интерполируется и кратко экстраполируется, чтобы скрыть шаг между snapshot-пакетами.

Транспортные частоты:

- input клиента: `30 Hz`, `unreliable_ordered`;
- snapshots хоста: `20 Hz`, `unreliable_ordered`;
- физика движущихся фонариков: максимум `10 Hz`, `unreliable_ordered`; после перехода в sleep отправляется финальное состояние и сетевой цикл отключается;
- создание игрока и служебные запросы: `reliable`.

Рубильник, питание двери, открытие двери и изменения инвентаря подтверждаются хостом и передаются надёжными RPC. Клиент отправляет только порядковый номер действия; цель повторно определяется серверным `RayCast3D`, поэтому клиент не назначает себе предмет и не открывает дверь напрямую.

Для двух игроков это создаёт небольшой и предсказуемый трафик. Прыжок и переключение фонаря передаются порядковыми номерами, поэтому потеря одного unreliable input-пакета не теряет действие навсегда.

## Запуск без консольных команд

### Если Godot установлен через Steam

Steam-версия редактора может поставляться со своей более старой `steam_api64.dll`. Windows загружает её раньше версии из GDExtension, из-за чего GodotSteam 4.21 сообщает `Error 127`.

Не нужно заменять DLL внутри установленного Steam-приложения. После первого получения проекта нужно закрыть Godot и один раз запустить:

`SETUP_NORTHERNLAB.cmd`

Он проверяет наличие обязательных файлов `addons/godotsteam/`, подготавливает изолированную копию редактора с совместимой `steam_api64.dll` и создаёт в корне проекта ярлыки:

`NorthernLab.lnk` (совместимый старый ярлык `NorthernLab - Godot.lnk` ведёт туда же)

Двойной клик сразу запускает игру через совместимую локальную копию GodotSteam runtime, без открытия редактора и без `F5`. Для работы со сценами используется `NorthernLab - Editor.lnk`. Установка Godot в Steam остаётся без изменений. Сгенерированные ярлыки и `tools/.local/` исключены из Git, потому что содержат локальные пути; на каждом компьютере их создаёт переносимый CMD-установщик.

### Проверка на двух компьютерах

На каждом компьютере:

1. Запустить Steam Client и войти в разные Steam-аккаунты.
2. Запустить игру ярлыком `NorthernLab.lnk`; редактор и `F5` для этого не нужны.
3. Хост нажимает `ESC` → `Играть с друзьями`. Игра откроет салон вертолёта и создаст Steam-лобби; после подключения меню автоматически закроется, чтобы можно было ходить.
4. Lobby ID постоянно виден в левом верхнем углу салона. Через `ESC` → `Показать Steam-лобби` его можно скопировать и отправить другу.
5. Второй игрок нажимает `ESC` → `Подключиться к другу`, вставляет Lobby ID и нажимает `Подключиться`.
6. Готовность можно переключать независимо — это информационный статус и она не блокирует запуск.
7. Хост начинает вылет красной консольной кнопкой впереди салона (`E`) либо через `ESC` → `Начать игру`. Это можно сделать сразу и в одиночку. Экран кратко затемняется, после чего экипаж переносится в тестовые комнаты базы; второй игрок также может подключиться позже.

Это интернет-соединение через Steam, а не LAN. Команды и ручной запуск тестовой сцены больше не нужны. Получение Steam-имени подтверждает работу Steam API, но не означает, что Overlay внедрён в процесс. В редакторе Lobby ID остаётся основным способом тестирования.

`ESC` в любой зоне открывает то же меню и ставит локальное дерево сцены на паузу. До вылета игроки свободно ходят по вертолёту; готовность остаётся информационной. После старта те же сетевые персонажи без пересоздания телепортируются в зону базы, поэтому Steam-сессия не разрывается. Игра запускается в полноэкранном режиме 1920×1080 с адаптивным растяжением интерфейса.

При ручном выходе из лобби, ошибке подключения или разрыве с хостом пустая сетевая сцена не остаётся на экране: игра возвращается в главную сцену и открывает меню с причиной завершения сессии.

### Из экспортированной сборки

Используется тот же ESC-интерфейс. Для проверки `Пригласить через Steam` нужна экспортированная сборка, запущенная через Steam: Overlay должен подключиться к процессу до/при создании графического устройства. Для раннего теста сборку можно добавить в библиотеку как стороннюю игру; штатный путь перед Playtest — загрузить одинаковую сборку под собственным Steamworks App ID. Оба игрока должны находиться в Steam под разными аккаунтами.

## App ID

Пока используется Steam App ID `480` (Spacewar), передаваемый напрямую в `steamInitEx()`. Для него Lobby metadata фильтруется тегом `northern_lab_story_coop_v1`, чтобы не показывать чужие тестовые лобби.

`steam_appid.txt` в репозиторий не добавляется и для релизной Steam-сборки не нужен.

До Steam Playtest или закрытого теста команде потребуется:

- собственный Steamworks App ID;
- доступ обоих разработчиков/тестировщиков к приложению или Playtest;
- замена `network/steam/app_id` в `project.godot`;
- проверка Invite Overlay и подключения на загруженной в Steam сборке.

Это не блокирует текущий прототип на App ID 480.

## Что ещё не входит в прототип

- host migration;
- синхронизация сюжетных флагов и сохранений;
- reconnect после обрыва;
- сетевой вариант production-персонажа;
- AI и сюжетные триггеры;
- голосовой чат;
- Steam authentication tickets и проверка версии билда перед входом.

Текущий вертикальный срез уже включает прогулочный pre-game lobby в вертолёте, host-authoritative вылет, рубильник, дверь, батарею, подбор и выпадение фонарика. Следующая безопасная задача Gameplay Programmer — проверить весь маршрут на двух Steam-аккаунтах, затем заменить мгновенный подлёт на синхронизируемую короткую полётную последовательность. Геометрию основной базы для этого менять не нужно.
