# Архитектура: запасы игрока — 14.11.2026

## Завершённая граница ответственности

GamePlayer владеет одним PlayerSupplies (RefCounted) на экземпляр персонажа. Он хранит детали крафта, изоленту, ресурс монтировки и запасные батареи. Это объект состояния с восстановлением и подготовкой данных, без узлов сцены, обработки кадров, поиска групп, визуальных эффектов и RPC.

Публичные свойства GamePlayer делегируют обращения этому объекту. Второго набора значений нет. Это сохраняемый фасад игрового API для рецептов, handoff и UI. Непосредственные игровые действия и авторитет по-прежнему контролирует GamePlayer; боеприпасы и топливо огнемёта принадлежат WeaponController/его компоненту.

write_snapshot() дописывает прежние четыре поля в уже созданный словарь игрока. Дополнительный словарь не создаётся. Коллекции копируются при публикации, как прежде, чтобы снимок не менялся вместе с живым состоянием. Старые ревизии отбрасываются игроком до изменения состояния запасов. Имена/аргументы/каналы RPC, сигналы, пути узлов и ключи сохранений не менялись. Порядок ключей словаря не является частью формата.

## Ограничения и дальнейшая граница

Это первый этап инвентаря, не завершённая перестройка всей архитектуры. Существующие публичные коллекции GamePlayer сохранены для совместимости; внешние операции пока обращаются к ним через фасад. Следующее логическое выделение — операции пополнения/расхода запасов с едиными доменными правилами, при сохранении проверок авторитета в игроке и транзакций передачи. Не вводятся глобальные менеджеры и дополнительные уровни наследования без отдельной ответственности.

Измерений FPS до/после не проводилось, прирост производительности не заявляется. Проверена структура работы: один объект на игрока, без новых кадровых обработчиков, без дополнительного словаря на снимок. Локальный ENet не заменяет проверку Steam на двух устройствах.
